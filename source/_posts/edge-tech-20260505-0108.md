## 引言

Structured Text（ST）作为IEC 61131-3五大编程语言中表达力最强的一种，正在成为边缘控制器开发的首选语言。相比梯形图（LD）的直观性和功能块图（FBD）的模块化，ST在处理复杂数学运算、字符串操作和算法逻辑时拥有不可替代的优势。然而，许多从LD转型的工控工程师写出的ST代码依然停留在"翻译梯形图"的阶段，未能发挥ST的真正威力。本文结合施耐德Modicon边缘控制器实战经验，分享7个让ST代码从"能跑"到"优雅"的高阶技巧。

## 技巧一：用枚举替代魔法数字

在边缘控制场景中，设备状态、工艺步骤常常用整数表示。直接使用数字（所谓"魔法数字"）让代码可读性极差，维护时更是一场灾难。

**反面示例：**

```pascal
IF iMotorStatus = 3 THEN
    qOutput := TRUE;
ELSIF iMotorStatus = 5 THEN
    qOutput := FALSE;
END_IF;
```

**推荐写法：**

```pascal
TYPE eMotorState :
(
    STOPPED    := 0,
    STARTING   := 1,
    RUNNING    := 2,
    STOPPING   := 3,  (* 原来的"3" *)
    FAULT      := 4,
    EMERGENCY  := 5   (* 原来的"5" *)
);
END_TYPE

VAR
    eMotor : eMotorState;
END_VAR

IF eMotor = STOPPING THEN
    qOutput := TRUE;
ELSIF eMotor = EMERGENCY THEN
    qOutput := FALSE;
END_IF;
```

枚举类型在EcoStruxure Machine Expert中支持自动补全和在线监控，调试时直接显示状态名而非数字，效率倍增。

## 技巧二：状态机用CASE替代嵌套IF

边缘控制器常需实现多步工艺流程，嵌套IF-ELSIF层层套叠，极难维护。CASE语句天然适配有限状态机（FSM），逻辑清晰且执行效率更高。

```pascal
CASE eStep OF
    00: (* 初始化 *)
        fbHeater(ENABLE := TRUE, TEMP := 80.0);
        IF fbHeater.AT_TEMP THEN
            eStep := 10;
        END_IF;

    10: (* 注胶 *)
        fbPump(START := TRUE, FLOW := 50.0);
        TON_Step(IN := TRUE, PT := T#5S);
        IF TON_Step.Q THEN
            fbPump(START := FALSE);
            TON_Step(IN := FALSE);
            eStep := 20;
        END_IF;

    20: (* 固化 *)
        TON_Cure(IN := TRUE, PT := T#30S);
        IF TON_Cure.Q THEN
            TON_Cure(IN := FALSE);
            eStep := 90;  (* 完成 *)
        END_IF;

    90: (* 完成 *)
        qDone := TRUE;
ELSE
    eStep := 00;  (* 非法状态自动恢复 *)
END_CASE;
```

## 技巧三：功能块封装复用逻辑

边缘控制器资源有限，代码复用不仅减少工程量，更降低出错概率。将常用功能封装为功能块（FB），通过输入输出参数化调用。

以边缘场景中常见的滑动平均滤波为例：

```pascal
FUNCTION_BLOCK fbMovingAvg
VAR_INPUT
    rInput   : REAL;
    nWindow  : INT := 10;  (* 窗口大小 *)
END_VAR
VAR_OUTPUT
    rOutput  : REAL;
END_VAR
VAR
    aBuffer  : ARRAY[1..50] OF REAL;
    nIdx     : INT := 1;
    rSum     : REAL;
    bFilled  : BOOL := FALSE;
END_VAR

// 移除最旧值，加入新值
rSum := rSum - aBuffer[nIdx] + rInput;
aBuffer[nIdx] := rInput;
nIdx := nIdx + 1;

IF nIdx > nWindow THEN
    nIdx := 1;
    bFilled := TRUE;
END_IF;

IF bFilled THEN
    rOutput := rSum / INT_TO_REAL(nWindow);
ELSE
    rOutput := rSum / INT_TO_REAL(nIdx - 1);
END_IF;
```

调用方仅需一行：

```pascal
fbTempFilter(rInput := rRawTemp, nWindow := 20, rOutput => rFilteredTemp);
```

## 技巧四：用指针与ADR/REF高效处理数组

在Modicon M580/M340中处理大数组时，逐元素访问效率低下。利用`ADR`获取地址、`REF`创建引用，可实现指针式高效遍历，尤其适合边缘控制器上的数据采集缓冲区操作。

```pascal
VAR
    aData : ARRAY[1..1000] OF REAL;
    pRef  : REFERENCE TO REAL;
    i     : INT;
END_VAR

FOR i := 1 TO 1000 DO
    pRef REF= aData[i];
    pRef := pRef * 1.05;  (* 批量增益校准 *)
END_FOR;
```

> **注意**：指针操作需谨慎，务必确保索引不越界。施耐德控制器支持运行时边界检查（`CheckBounds`功能块），建议在调试阶段启用。

## 技巧五：结构体组织边缘数据模型

边缘控制器面对的不再是简单I/O，而是MQTT报文、OPC UA节点、REST API响应等复杂数据结构。用STRUCT将关联数据组织在一起，既清晰又便于传递：

```pascal
TYPE stEdgeSensor :
STRUCT
    sDeviceID    : STRING[32];
    rValue       : REAL;
    rMinLimit    : REAL := -40.0;
    rMaxLimit    : REAL := 125.0;
    tsTimestamp  : DT;
    eQuality     : eDataQuality;
    bAlarmActive : BOOL;
END_STRUCT
END_TYPE

VAR
    stTempSensor : stEdgeSensor;
    stPressSensor: stEdgeSensor;
END_VAR
```

将结构体作为功能块输入，一个FB即可处理所有传感器类型——这就是ST的泛化能力。

## 技巧六：定时器TON的防抖与链式调用

边缘控制器采集的数字量输入常常伴随抖动，TON定时器做软件防抖是最简洁的方案：

```pascal
// 防抖：信号稳定200ms后才认为有效
TON_Debounce(IN := iRawSignal, PT := T#200MS);
qStableSignal := TON_Debounce.Q;

// 链式延时：先延时2s启动泵，再延时5s开阀门
TON_PumpDelay(IN := qStableSignal, PT := T#2S);
fbPump(START := TON_PumpDelay.Q);

TON_ValveDelay(IN := TON_PumpDelay.Q, PT := T#5S);
fbValve(OPEN := TON_ValveDelay.Q);
```

## 技巧七：利用AT覆盖实现协议映射

在边缘控制器与第三方设备通信时，常需要将字节流映射到结构化变量。`AT`关键字实现变量重叠声明，免去手动拆解字节的繁琐：

```pascal
VAR
    abyRawFrame : ARRAY[1..8] OF BYTE;
    stMapped AT abyRawFrame : STRUCT
        wHeader  AT %B0 : WORD;     (* 字节1-2 *)
        rValue   AT %B2 : REAL;     (* 字节3-6 *)
        byChksum AT %B6 : BYTE;     (* 字节7 *)
        byTail   AT %B7 : BYTE;     (* 字节8 *)
    END_STRUCT;
END_VAR
```

收到Modbus RTU报文后，直接写入`abyRawFrame`，`stMapped`自动解析——零拷贝、零代码。

## 结语

Structured Text不是"高级版的梯形图"，而是一种有自身设计哲学的工程语言。枚举提升可读性、CASE驾驭状态机、功能块封装复用、结构体建模数据——这七个技巧的核心思想是**让代码表达意图而非实现细节**。在边缘控制器越来越"智能"的今天，写出优雅的ST代码不仅是工程素养的体现，更是系统可靠运行的基石。
