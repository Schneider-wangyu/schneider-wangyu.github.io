## 引言：为什么边缘控制器更值得用ST语言

在工业自动化的编程语言选择中，梯形图（LD）一直是工控工程师的"母语"。但随着边缘控制器（如施耐德Modicon M262/M580）承担越来越多的复杂计算、协议转换和数据处理任务，Structured Text（ST）语言的优势愈发明显：**紧凑的数学表达、灵活的数据结构操作、与IT语言的相似性**，使它成为边缘控制场景下的首选编程语言。

本文结合施耐德EcoStruxure Machine Expert开发环境，分享ST语言在边缘控制器上的实战编程技巧，涵盖数据结构设计、通信协议处理和调试优化三大核心场景。

## 一、用STRUCT和ARRAY设计高效数据结构

边缘控制器通常需要处理大量I/O映射和通信数据，合理设计数据结构是代码质量的第一步。

### 1.1 结构体封装设备参数

以变频器控制为例，将所有相关参数封装为一个STRUCT，避免全局变量泛滥：

```st
TYPE ST_VFD_Control :
STRUCT
    bStart       : BOOL;       // 启动命令
    bStop        : BOOL;       // 停止命令
    bFaultReset  : BOOL;       // 故障复位
    rFreqRef     : REAL;       // 频率给定 (Hz)
    rFreqAct     : REAL;       // 运行频率反馈
    rCurrentAct  : REAL;       // 运行电流反馈 (A)
    bRunning     : BOOL;       // 运行状态
    bFault       : BOOL;       // 故障状态
    dwFaultCode  : DWORD;      // 故障代码
END_STRUCT
END_TYPE
```

在程序中声明实例后，通过`.`操作符访问成员，语义清晰且易于维护：

```st
VAR
    gVFD1 : ST_VFD_Control;
END_VAR

// 启动逻辑
gVFD1.bStart := TRUE;
gVFD1.rFreqRef := 50.0;
```

### 1.2 数组+FOR循环批量处理I/O映射

施耐德M580的X80 I/O模块使用Device DDT非定位变量，需要映射到%MW寄存器才能与HMI通信。用FOR循环批量处理，比逐个赋值高效得多：

```st
VAR
    aAI_Raw    : ARRAY[1..16] OF INT;    // 原始模拟量
    aAI_Scaled : ARRAY[1..16] OF REAL;   // 工程量
    i          : INT;
END_VAR

FOR i := 1 TO 16 DO
    aAI_Scaled[i] := INT_TO_REAL(aAI_Raw[i]) * 100.0 / 32767.0;
END_FOR;
```

> **技巧**：FOR循环的边界必须与数组声明一致，否则会触发边界溢出异常。建议使用常量定义数组长度，便于统一修改。

## 二、Modbus通信的ST编程模式

边缘控制器作为网关，Modbus通信是最常见的协议对接场景。以下是M262通过Modbus TCP读写从站的标准ST编程模式。

### 2.1 通信状态机设计

用CASE语句实现通信状态机，比多层嵌套IF更清晰、更可维护：

```st
CASE eCommState OF
    0:  // 空闲等待
        IF bCommTrigger THEN
            eCommState := 10;
        END_IF;

    10: // 发送读请求
        MB_TCP_Read(bEnable := TRUE,
                    dwReadAddr := 100,
                    iReadLen := 10,
                    pwReadData := ADR(aReadBuffer));
        eCommState := 20;

    20: // 等待响应
        IF MB_TCP_Read.bDone THEN
            // 数据处理...
            eCommState := 30;
        ELSIF MB_TCP_Read.bError THEN
            dwErrorCode := MB_TCP_Read.wError;
            eCommState := 99;  // 跳转错误处理
        END_IF;

    30: // 发送写请求
        MB_TCP_Write(bEnable := TRUE, ...);
        eCommState := 40;

    40: // 等待写完成
        IF MB_TCP_Write.bDone THEN
            eCommState := 0;   // 回到空闲
        END_IF;

    99: // 错误处理
        bCommAlarm := TRUE;
        eCommState := 0;
END_CASE;
```

### 2.2 超时保护机制

通信必须加超时保护，防止因从站无响应导致程序卡死：

```st
VAR
    tCommTimeout : TON;       // 超时定时器
    tTimeoutSet  : TIME := T#3S;
END_VAR

tCommTimeout(IN := (eCommState = 20 OR eCommState = 40),
             PT := tTimeoutSet);

IF tCommTimeout.Q THEN
    eCommState := 99;  // 超时跳转错误
    dwErrorCode := 16#FFFF;  // 自定义超时码
END_IF;
```

## 三、边缘控制器调试实战技巧

### 3.1 利用%MW观察区快速调试

在Machine Expert中，将关键中间变量映射到%MW观察区，可以通过HMI或Web Server直接监控，无需在线模式：

```st
// 调试观察区映射
%MW100 := INT_TO_WORD(eCommState);    // 通信状态
%MW101 := REAL_TO_DWORD(rFreqRef);    // 频率给定
%MW102 := DWORD(dwFaultCode);         // 故障代码
```

### 3.2 边缘控制器Web诊断

Modicon M262内置Web Server，浏览器直接访问控制器IP即可查看：
- **系统诊断**：CPU负载、内存使用、通信统计
- **变量监控**：在线读写%MW/%I/%Q变量
- **固件管理**：远程升级固件版本

> **注意**：Web Server功能需要在Device配置中启用，默认端口80，建议修改为非标准端口并启用HTTPS。

### 3.3 ST代码性能优化要点

| 优化项 | 说明 |
|--------|------|
| 避免浮点除法 | 用乘法替代：`x / 10.0` → `x * 0.1` |
| 减少临时变量 | 复合表达式代替中间赋值 |
| 合理使用跳转 | 循环体内避免频繁调用功能块 |
| 数组边界检查 | 使用`LIMIT()`函数钳位索引值 |

## 四、IEC 61131-3五种语言选型建议

| 语言 | 最佳场景 | 边缘控制适用度 |
|------|----------|---------------|
| **ST** | 复杂运算、协议处理、数据处理 | ★★★★★ |
| **FBD** | 功能块组合、信号流处理 | ★★★★☆ |
| **LD** | 简单逻辑、电气人员易读 | ★★★☆☆ |
| **SFC** | 顺序工艺流程控制 | ★★★★☆ |
| **IL** | 底层优化（已不推荐） | ★☆☆☆☆ |

在边缘控制场景中，**ST + FBD**的组合是最优方案：ST处理计算与通信，FBD处理信号流与功能块互联，两者在Machine Expert中可自由混合调用。
