边缘控制

Structured Text 编程实战：从数据类型到边缘控制器的高效代码设计

引言

在边缘控制器（如施耐德 Modicon M580 ePAC、M251 或 Soft dPAC）上编写控制逻辑时，Structured Text（ST）是 IEC 61131-3 五种语言中最接近高级语言的选择。相比梯形图（LD），ST 在处理复杂算法、数据处理和通信任务时效率远高于图形化语言；相比指令表（IL），ST 的可读性和可维护性又更胜一筹。本文从数据类型选型、模块化设计、性能优化和调试技巧四个维度，分享边缘控制器 ST 编程的实战经验。

一、数据类型选型：别让类型成为”定时炸弹”

BOOL 类型：只用布尔量，别用 INT 冒充

一个常见的不良习惯是用 INT 甚至 WORD 存储开关信号。正确的做法是——开关、限位、安全门等二值信号一律用 BOOL。

反例（错误）：
iecst
IF iSensorStatus = 1 THEN
Q_Output := 1;
END_IF

正例（正确）：
iecst
IF bSensorStatus THEN
Q_Output := TRUE;
END_IF

数值类型：INT、DINT 还是 REAL？

边缘控制器处理模拟量采集（4-20mA / 0-10V）时，推荐法则：

数据范围 推荐类型 原因
0~32767 整数 INT 紧凑，2 字节
±2^31 范围整数 DINT M580 原生 32 位处理
浮点运算 REAL 配合 PID、滤波算法
累加计数值 UDINT 无符号防溢出

实战建议： 不要贪图方便全用 INT。边缘控制器上的 M580 CPU 是 32 位 ARM（Cortex-A9）架构，DINT 运算效率接近 INT，但 INT 到 DINT 的隐式转换反而会消耗额外扫描周期。

iecst
(* 推荐：显式类型转换，让代码意图清晰 )
VAR
aiRaw : INT; ( 来自模拟量模块的原始值 )
diScaled : DINT; ( 缩放后的工程值 )
fPercent : REAL; ( 百分比输出 *)
END_VAR

diScaled := DINT(aiRaw) * 100 / 27648; (* 0-27648 归一化到 0-100 *)
fPercent := REAL(diScaled) / 100.0;

TIME 类型与 Duration 陷阱

iecst
(* 正确写法：用 TIME# 前缀 )
TON_1(IN := bStart, PT := T#5S);
TON_2(IN := bPulse, PT := T#2.5S); ( 小数也是标准语法 *)

(* 边沿检测的简洁写法 *)
IF bSensor AND NOT bSensor_prev THEN
Pulse_Counter := Pulse_Counter + 1;
END_IF
bSensor_prev := bSensor;

二、模块化设计：写好 FUNCTION_BLOCK 的四个要领

1. 接口先行，实现后补

在写 FB 算法体之前，先定义好 VAR_INPUT、VAR_OUTPUT：

iecst
FUNCTION_BLOCK FB_PID_Edge
(* 边缘侧 PID 控制器 - 带抗积分饱和 )
VAR_INPUT
Setpoint : REAL; ( 设定值 )
Feedback : REAL; ( 反馈值 )
Kp : REAL := 1.0; ( 比例增益 )
Ti : TIME := T#1S; ( 积分时间 )
Td : TIME := T#0S; ( 微分时间 )
Enable : BOOL;
Reset : BOOL; ( 复位 PID )
END_VAR
VAR_OUTPUT
Output : REAL; ( 控制输出 )
IsSaturated : BOOL; ( 是否饱和 )
END_VAR
VAR
Error : REAL;
Integral : REAL;
Derivative : REAL;
Prev_Feedback : REAL;
dt_s : REAL; ( 采样间隔秒数 *)
Timer : TON;
END_VAR

这种”接口契约式”开发，让调用方直接看到全部参数，无需翻阅内部实现。

2. 内部变量上限原则

单个 FB 的内部变量超过 20 个时，使用 STRUCT 拆分子结构：

iecst
TYPE ST_PID_Tuning :
STRUCT
Kp : REAL; (* 比例系数 )
Ti : REAL; ( 积分时间（秒） )
Td : REAL; ( 微分时间（秒） )
OutputMax : REAL; ( 输出上限 )
OutputMin : REAL; ( 输出下限 *)
END_STRUCT
END_TYPE

3. 最大代码行数：40 行法则

单个功能块（FB）或函数（FUN）的算法代码不超过 40 行。超过说明职责过多，应拆分子 FB。

4. 全局变量的唯一合法用途

仅在硬件映射层使用 VAR_GLOBAL，业务逻辑层零全局变量——通过 VAR_IN_OUT 传递引用。

三、性能优化：让边缘控制器”跑得更轻快”

任务周期分配

在 SoMachine / EcoStruxure Control Expert 的任务配置中，合理分配扫描周期：

  • 10ms 任务：高速 IO 和运动控制
  • 50ms 任务：PID 回路调节
  • 200ms 任务：OPC UA 数据发布
  • 1s 任务：日志记录和统计

不要在 10ms 任务里做浮点数组运算或字符串拼接。

循环优化：FOR 循环注意数组边界

iecst
(* 推荐：编译时已知的循环上限 *)
CONSTANT
MAX_SENSORS : INT := 256;
END_VAR
FOR i := 0 TO MAX_SENSORS - 1 DO
arrProcessed[i] := arrRaw[i] * 10;
END_FOR

条件语句：CASE vs IF 链

iecst
(* 三个以上互斥分支 → 用 CASE，执行效率更高 )
CASE iState OF
0: ( Idle )
bRunning := FALSE;
1: ( Start )
bRunning := TRUE;
2: ( Process )
IF tTimer.Q THEN
iState := 3;
END_IF;
3: ( Done )
bDone := TRUE;
iState := 0;
ELSE
iState := 0; ( 防死锁 *)
END_CASE

四、调试技巧：快速定位问题

变量 Watch 分组

SoMachine 的 Watch 窗口按功能分组追踪变量，常用的分组策略：

分组名 包含变量
IO_Inputs 所有数字量/模拟量输入
PID_Loops 各回路 SP、PV、CV
Alarms 报警状态字、累计次数
Comm_Status OPC UA 连接状态、MQTT 心跳

断点调试三步法

  1. 在怀疑的赋值语句行设置断点
  2. 单步观察变量变化
  3. 条件断点只在特定条件满足时暂停

在 SoMachine 中，断点配合 Watch List 是排查逻辑错误最有效的方式。

ST 在线监控

iecst
(* 在线状态下，变量的当前值会实时显示 )
IF bFault THEN
diErrCode := 1001; ( 在线监视时直接看到此值更新 *)
Q_Alarm := TRUE;
END_IF

使用 Assertion 检查边界

iecst
{IFDEF DEBUG}
ASSERT(aiRaw >= 0, “”模拟量输入不能为负””);
ASSERT(diScaled <= 10000, “”工程值超限””);
{ENDIF}

五、ST 语言选型建议：何时用，何时不用

场景 推荐语言 理由
简单启停逻辑 LD（梯形图） 电气人员直观
模拟量处理/计算 ST 数学表达能力强
状态机/流程控制 SFC + ST 动作 结构清晰
高速计数/编码器 ST + 底层指令 纳秒级响应
安全联锁 FBD 信号流一目了然
通信解析/报文处理 ST 位操作和数组处理

总结： 对于边缘控制器上的复杂逻辑（工业网关协议转换、边缘 AI 推理调度、多回路协调控制），ST 是当之无愧的首选。在 Modicon M580 这类 ARM 架构边缘控制器上，32 位运算、浮点计算和数组处理能力出色，配合 SoMachine 完善的调试工具链，能显著提升边缘侧应用的开发效率和运行稳定性。
