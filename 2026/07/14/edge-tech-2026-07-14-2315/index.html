边缘控制

从 ECC 到边缘节点：用 IEC 61499 功能块在 EcoStruxure 开放自动化平台实战编程

为什么边缘控制需要 IEC 61499

传统 PLC 程序多由 IEC 61131-3 梯形图/ST 集中编写，应用与硬件强耦合，跨设备复用困难。当控制逻辑要下沉到多个边缘节点（M580 ePAC、M251、Soft dPAC）并与云端协同时，IEC 61499 以”功能块即微服务”的思路，把事件驱动的分布式应用与具体硬件解耦，正好契合边缘控制的需求。

施耐德 EcoStruxure Automation Expert（EAE）就是基于 IEC 61499 的开放自动化平台。它的工程由 Buildtime（开发环境）+ Runtime（运行时，含 Soft dPAC）+ 设备固件（M251/M580/Altivar） 三部分组成。

基本功能块的内部骨架

一个 Basic FB 由四部分构成：

  • 接口：事件输入/输出（EI/EO）+ 数据输入/输出（DI/DO）
  • ECC（执行控制图表）：决定”哪个事件触发哪段算法”
  • 算法（Algorithm）：用 IEC 61131-3 ST 或 C 编写
  • 内部变量：保持状态

在 ECC 中，把 REQ 事件关联到 ALG_COUNT，再把 ALG_COUNT 关联到 CNF 事件输出；INIT 事件则绑定 ALG_RESET 将 CV 清零。这样就实现了事件驱动、状态保持的模块。

FBD 设计的两个要点

  1. **事件是”时序”，数据是”载荷”**：连线时先保证事件链完整（REQ→CNF→REQ…），再连数据。只连数据不连事件，算法不会执行。
  2. 把”设备相关”下沉到 Service Interface FB：IO、OPC UA 发布等封装成 SIFB，业务逻辑用 Composite FB 编排，便于向不同边缘节点映射部署。

部署到边缘节点

在 Buildtime 中新建 Device，类型选 Modicon M580 ePAC 或 Soft dPAC，填写 IP 与固件版本；右键 Application → Deploy 即可把功能块网络下发到边缘控制器。需要上云时，在 SIFB 中启用 OPC UA PubSub，把 CV、Q 经 TSN 确定的网络周期性发布到云端分析服务。

小结：把控制逻辑写成可复用、事件驱动的 IEC 61499 功能块，再用 EAE 一键映射到多类边缘硬件，是构建柔性产线与边缘+云协同控制的关键一步。
